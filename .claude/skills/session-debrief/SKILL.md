# Session debrief

A transcript is the only honest measurement of content quality. It shows what
was actually taught, what was skipped, what the trainer had to invent live,
and where the room got lost. Run this before building the next session.

## Read the whole transcript first

Do not skim and do not summarise early. Read it in order, because the value is
in the sequence: where a question interrupts, what the trainer improvises next,
and what never gets reached.

## The five measurements to extract

| Measurement | How to get it | What it means |
|---|---|---|
| **Slides never reached** | Map the last topic taught to the deck | Content sitting too late in the deck |
| **Minutes of content not in the deck** | Count improvised stretches | Gaps the deck should have carried |
| **Live replacements** | A framework stated then abandoned for a simpler one | Rigour beat teachability, and lost |
| **Repeated questions** | The same confusion raised twice | A missing slide, not a slow room |
| **Prior-knowledge misses** | Terms the room asked to have explained | The build assumed knowledge nobody checked |

Report these as a table with timestamps. A number with a timestamp cannot be
argued with; an impression can.

## The gap table

One row per break, three columns: what broke, the transcript evidence with a
timestamp, and what it means about the build. Never assert a gap without a
quotable moment behind it.

## Root causes, stated plainly

Own the causes rather than describing symptoms. The four that recur:

- The build assumed prior knowledge nobody verified
- Sizing was done by slide count rather than by delivery minutes
- A rule was over-applied, stripping something the delivery needed
- The most defensible framework was chosen over the most teachable one

## Binding rules, not intentions

Every root cause converts into a checkable rule with a mechanism. "Be more
concise" is not a rule. "Budget 2.5 minutes a slide for an interactive room,
mark 25 slides core, list the rest as a ranked cut list" is.

## The recoverable-assets call

Every artefact built for the session gets one of four verdicts, with the
reason:

| Verdict | Meaning |
|---|---|
| **Keep** | It worked. Note precisely why so the pattern can be repeated |
| **Repair** | The content is sound, the format or placement failed |
| **Demote** | Correct but not teachable at this level. Keep as an appendix |
| **Retire** | It tested something never taught, or it assumed material never reached |

## Two things to check before writing a word of the next session

**What does this room not know.** The transcript names it, usually in the
first ten minutes and again whenever somebody asks what an acronym means.

**What did the trainer invent that landed well.** Improvised content that
generated discussion is the strongest signal in the whole transcript. Put it
in the deck, scripted, and give it a slide.

## Tone

Do not soften the numbers and do not perform contrition. State the gap,
state the cause, state the mechanism, move to the recovery. The value of a
debrief is that it is uncomfortable and specific.
