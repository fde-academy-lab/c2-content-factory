# Curriculum map, phase level by design

The week-by-week calendar shifts between cohorts, so this map holds only what stays stable: the four phases, the broad topic families inside each, the skills each phase unlocks, and one fixed landscape canvas that the coverage shading always draws from. Place every session against this file, and state a week number only when the user supplies one in the prompt.

Provenance: the phase names and spans, the session lattice, the project ladder and the consultancy produce lists are established from the programme curriculum build; the topic families are compiled from programme evidence and are the first thing to correct when this file is redlined; the landscape canvas and the skills-unlocked phrasing are constructions written for this skill.

## The four phases

| Phase | Indicative span | Broad topic families | Skills unlocked when the phase closes |
|---|---|---|---|
| Phase 1, Foundations | About W1 to W4 | How LLMs actually work (tokens, context windows, model families), prompting and structured output, the vocabulary of the GenAI stack, first sight of the agentic loop, and hackathon-style building. | The learner can read and speak the GenAI stack, drive a model with well-built prompts, and recognise the agentic loop inside any AI product. |
| Phase 2, Core Build | About W5 to W12 | Retrieval and RAG end to end (chunking, embeddings, rerankers, grounding), agents and tool use, orchestration frameworks such as LangGraph, and first evaluation habits. | The learner can build a grounded RAG system and defend its retrieval choices with measured numbers, and can wire tools into an agent and control its loop. |
| Phase 3, Deployment Depth | About W13 to W20 | Production posture: evaluation and observability, guardrails and safety, cloud platform depth in the AWS Bedrock and AgentCore families, token economics, caching and the cost levers. | The learner can take a working build to production posture, with evals, guardrails, tracing and a cost account a client would sign off. |
| Capstone Engagement | About W21 to W32, plus three sprint weeks | Multi-agent systems (a second framework such as Agno enters here), the capstone engagement run end to end, portfolio and case studies, and interview readiness. | The learner can run a client-shaped engagement end to end: scope it, estimate it, build with a team of agents where that pays, demo it, and write the case study. |

## The landscape canvas, fixed on purpose

Nine territories, held stable so the "covered so far" shading means the same thing in every note across the programme.

| # | Territory | What lives here |
|---|---|---|
| 1 | Model foundations | How LLMs work, with tokens, context windows, and model families with their trade-offs. |
| 2 | Prompting and structured output | Prompt construction, output contracts, and function-shaped responses. |
| 3 | Retrieval and RAG | Chunking, embeddings, rerankers, grounding and citation. |
| 4 | Agents and tool use | The agentic loop, tool wiring, and orchestration frameworks. |
| 5 | Multi-agent systems | Teams of agents, handoffs, and coordination frameworks. |
| 6 | Evaluation and observability | Eval sets, answer metrics against trace metrics, and tracing in production. |
| 7 | Safety and guardrails | Content filters, denied topics, grounding checks and policy. |
| 8 | Platform, deployment and cost | Cloud AI platforms, serving, token economics, caching and the cost levers. |
| 9 | Consulting delivery | Discovery, scoping, proposal, SOW, estimate, demo and case study. |

For the shading, map phases to territories this way: Foundations claims 1 and 2 and opens 4; Core Build claims 3 and 4 and opens 6; Deployment Depth claims 6, 7 and 8; Capstone Engagement claims 5 and completes 9. Territory 9 runs across all phases through the Wednesday consultancy thread, so shade it progressively rather than inside one phase.

## The week lattice, stable across cohorts

| Session | Day | Shape |
|---|---|---|
| Tech 1 | Tuesday | The core technical session of the week. |
| Consultancy | Wednesday | The consulting thread runs as one sequence from the FDE seat to graduation, producing proposals, SOWs, estimates and case studies. |
| Tech 2 | Thursday | The second technical session, building on Tuesday. |
| Apply | Saturday | Labs and guided builds of 2 to 3 hours, which become a 1 hour mentor check-in in project weeks. |
| Sunday sessions | Sunday | Recurring masterclasses, context-setting sessions and clinics. |

## The project ladder and Client Zero

Projects rise in nine steps from an opening hackathon through the mini projects, Project 5, Project 6 and the capstone sprints to demo week. Client Zero is the standing client every project is set inside, so a study note may anchor its use cases to Client Zero whenever the session did.

## What the consultancy thread produces in the later phases

Phase 3 produces a demo script for every project review, a domain map of one Client Zero unit, Proposal 1 through peer review with its SOW, a DCI reading with the R2P time trial, and a skills inventory with an updated resume. The capstone produces a WBS, RACI and sprint plan, up to five case studies with a portfolio narrative, mock interview feedback, the capstone communication plan and scope, a rehearsed panel presentation, and the consulting readiness evaluation.

## How a note uses this file

- Draw the curriculum strip from the four-phase table, with this session's phase in colour and the other phases greyed.
- Shade the landscape map cumulatively: every territory claimed by completed phases, plus whatever this session adds.
- Borrow the skills-unlocked language when writing the header promise and the takeaways, so the note speaks in capabilities rather than topic labels.
- Never print week numbers from this file, because the spans above are indicative and the calendar belongs to the cohort.
