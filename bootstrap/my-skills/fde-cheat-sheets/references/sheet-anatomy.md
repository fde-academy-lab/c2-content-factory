# Sheet anatomy, locked

Compiled from what the strong public exemplars share (algorithm-chooser flowcharts, card-grid variant sheets, column-style syntax references) and from reference-sheet research: one anchor visual that organises everything, consistently styled blocks instead of flowing prose, colour as a function code, five to nine visible chunks to match working memory, question-phrased headers to trigger recall, and ruthless curation.

## The four fixed parts

1. Title band. The sheet's name in Poppins Bold with a one-line promise underneath stating what the reader can retrieve here, and a small source-and-date line at the right edge so the sheet declares when its facts were verified.
2. The anchor visual. The largest block on the page, placed top left, drawing the whole concept as one map, flow, decision tree or labelled landscape. The anchor test governs it: alone, it should still recap the scope.
3. The block grid. Five to nine blocks composed from the palette below, in the fixed colour code, each block answering one question the reader's moment produces.
4. The foot strip. A full-width micro-glossary (six to ten terms at six to ten words each) or the mnemonic when it deserves the spotlight.

## The block palette

| Block | What it holds | Reach for it when |
|---|---|---|
| Definition cards | The scope's core terms as short cards, each a term plus a compressed meaning. | The scope's vocabulary is the barrier. |
| Variant cards | The types of the thing, numbered, one line each, with a micro-diagram when a shape distinguishes them. | The scope is a family (types of RAG, agent protocols, prompt patterns). |
| Decision table | Rows of "when you see this, reach for this", the seeing side concrete. | The reader must choose between options under time pressure. |
| Numbers worth memorising | The three to six figures that win arguments, each with source and year printed beside it. | The scope has measured results a reader will quote. |
| Rules of thumb | Working rules in full sentences, each with its breaking point stated. | Practitioners run on heuristics the reader should inherit consciously. |
| Traps | The mistakes that actually bite, drawn from real incident write-ups and engineering posts where findable. | Every technical scope; this block is near-mandatory. |
| Moves and syntax | Commands, API shapes or code idioms as compressed lines in the code style. | The scope is hands-on-keyboard. |
| Say it in the room | One or two client-safe sentences that state a trade-off out loud. | The scope will be spoken about to non-technical buyers, so almost always for FDEs. |
| Mnemonic box | An acronym or memory device, invented ones welcome, labelled "coined for this programme". | One exists that decodes the concept in the right order; never force one. |

## The colour code, fixed across every sheet

Rose fill carries definitions and variants. A pink border carries decisions and moves. Dark navy carries numbers and code. A magenta left bar carries traps and warnings. The mnemonic sits in a rose box with a pink border and its coined label. Learners learn this code once and then read every sheet faster, so no sheet trades it for novelty.

## Density rules

- Five to nine blocks per page, and white space is load-bearing: a cramped sheet fails the ten-second scan even when every fact on it is right.
- Cells, cards and the foot strip may use short imperative clauses ("keep BM25 beside embeddings"), because glance speed wins there; rules of thumb, traps and say-it-in-the-room lines stay full sentences, because those get read, believed and repeated.
- Block titles may be phrased as the question the reader brings ("Which retrieval do I reach for?"), since a question header triggers recall where a topic label triggers nothing.
- Bold the retrieval keys inside blocks (the term, the number, the command), never whole lines.
- Roughly balance the sheet across definitions, moves and evidence; a sheet that is all definitions is a glossary, and a sheet that is all moves assumes vocabulary the reader may lack.

## Mnemonic rules

An invented acronym or device must decode the concept in the right order, be pronounceable or otherwise sticky, and recap rather than decorate; it carries the label "coined for this programme" so nobody cites it outward as standard vocabulary. Reusing the scope's own name as the device is the strongest form when it lands. When nothing genuinely sticky exists, the sheet ships without one.

## The Markdown companion

The same blocks flattened into sections in the same order, with the anchor and any micro-diagrams referenced as image files beside the file, so the sheet reads properly in a GitHub repo. The companion carries the same verification line as the title band.
